{# ── Fetch ── #}
PubMed Fetch Settings

These credentials are shared across all users. The fetch process queries PubMed using each user's search profiles and calls the Unpaywall API to look up open-access PDF links for any papers found.

An API key raises the rate limit to 10 requests per second, which speeds up fetching significantly when multiple users have many search profiles. Keys are free and available at ncbi.nlm.nih.gov.
Required by both the NCBI E-utilities and the Unpaywall API. Use an address monitored by someone at your organisation in case either service needs to contact you about usage.

Running a manual fetch

Clicking "Run fetch now" starts the fetch process immediately in the background for all users whose fetching is enabled. It runs exactly as the scheduled fetch would, respecting each user's search profiles, lookback window, and quartile filter. Check the Logs tab to see progress and results. This is useful after adding new search profiles or when setting up a new user.

Testing and sending manually

"Send test email" delivers a single message to your own account address to verify the connection and credentials are working. "Send digest now" runs the full digest process immediately for all users, exactly as the scheduled run would, and respects each user's suppress-empty-digest preference. Both run in the background; check the Logs tab for results.

Rankings

About journal ranking data

Journal quartile rankings and CiteScore values are fetched directly from the Elsevier Scopus API. Q1 journals fall in the top 25% by CiteScore for their subject area; Q4 are in the bottom 25%.

An API key is required. Free institutional and individual keys are available at dev.elsevier.com. Once the key is saved, click Refresh now to fetch all journals in the background (typically ~10 minutes). The refresh writes to data/scopus_journals.csv and a live progress bar is shown below. Without ranking data, all journals appear as Unranked and quartile filtering is inactive.

Re-run the refresh once a year to pick up newly ranked journals and updated CiteScore values.

Publisher name shortcuts

Publisher names from PubMed are often long. You can define shorter display names here and they will appear everywhere in the interface and in email digests instead of the full name.

The list is pre-populated with every publisher found in your database. Leave the short name blank to keep the original. Changes take effect immediately on save.

Checking Predatory? marks a publisher as predatory or otherwise suspicious. Its name will then appear in muted red throughout the feed, on paper pages, and in email digests, so potentially unreliable sources are immediately visible.

{# ── LLM ── #}

LLM integration

Configure one or more LLM providers below, then assign each action to the provider that should handle it. Four actions are supported:

  • Abstract Highlights — up to 5 bullet-point highlights generated automatically from each paper's abstract.
  • Search Profile Improvement — sends rated papers to get query improvement suggestions (requires user access toggle).
  • Topic Term Suggestions — suggests MeSH-term-to-topic assignments for confirmation (requires user access toggle).
  • Feed Recap — synthesises selected feed papers into a prioritised briefing (requires user access toggle).
